# Glasswork 每日学习 05｜用空状态说明问题，而不是只显示“暂无数据”

## 想解决什么

“没有内容”只是外观，背后可能是首次使用、筛选无匹配、全部处理完、加载失败或权限不足。先判断原因，再给相应的下一步。空状态小到可以只占表格一行；只有用户真的需要理解整页结构时，才考虑一张简化线框。小空间不要用大插画把主操作推远。

## 怎么落到检索工作台

以下仅为合成示例，不代表任何项目界面已经改动。

| 场景 | 显示和动作 |
| --- | --- |
| 搜索无匹配 | 保留关键词、筛选和表头；在结果区用一行解释。提供“清除筛选”，保留搜索词，让用户知道放宽了什么。 |
| 请求失败 | 在失败的结果区域说“结果暂未加载”，提供重试；不要渲染为 0 条，也不要暗示已核实记录不存在。 |
| 缺少证据 | 记录正常展示；仅在证据区域写“本条暂未关联证据”，不把缺少文件误写成测试通过或整改完成。 |

## 实现和验收

- 搜索返回时用明确状态（查找中、成功有记录、成功无匹配、失败）选择文案。搜索和状态区仍可操作；搜索词、筛选与结果数的口径一致。清除筛选只改筛选，不清空关键词；有独立清除搜索按钮时，把两者的动作分开。
- 表格要读起来像原表，而不是弹出一张空白宣传卡。保留架构、列标题和位置。焦点继续留在触发操作处，结果变化用简短的无障碍状态播报。不靠动画、颜色或装饰图去表达失败。
- 5 分钟练习：用同一条虚构的 740 MHz 记录，刻意选中“不匹配”的状态；然后清除该筛选，确认关键词仍在、记录重现。再模拟请求失败，对照是否出现“重试”，且没有显示为零条。最后进详情模拟无附件，确认记录仍可查、只在证据区说明缺项。
