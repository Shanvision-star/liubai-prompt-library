```text
分析 http://sprites.ai，使用我们自己的 UI 制作一支产品宣传片，不要使用通用组件。

<direction>
达到 Dribbble 水准的 UI 动效。只有一个形状，绝不切镜：每个状态都是同一个元素改变尺寸、圆角半径和颜色，同时其内部内容伴随短暂模糊而替换。光标通过真实的点击和拖动驱动每一次变化。暖灰色画布、黑白组件、一种强调色（#FD9543），使用 Geist。处处使用弹簧运动，最多只允许极轻微的过冲。镜头通过缩放让每个状态占满画面。最后一帧 = 第一帧，从而形成循环。
禁止：弹跳式缓动、粒子、辉光、UI 控件外观上的渐变、粗细不一致的图标描边、无事发生的空档，以及任何看起来像模板的东西。
</direction>

<structure>
120 BPM，7 个小节，每一拍都有内容。
连接广告账户（Meta、Google、LinkedIn、TikTok、Reddit 的 logo） → 加载器 → 对勾 → 提示输入栏打出 "Launch ads that convert"（投放能带来转化的广告） → 灵动岛显示 "Researching 42 competitors"（正在研究 42 个竞争对手） → Ads Library 广告库中由真实广告组成的广告墙滚动，并停在一个表现出色的广告上 → 审批卡片 → Approve & launch（批准并投放） → 拖过最大值时会拉伸的预算滑块 → Autopilot 自动运行开关 → 开关滑块变成在不同渠道间移动的液态标签页指示条 → ROAS 图表自行绘制，悬停时显示提示气泡 → ⌘K → 输入 "pause"（暂停） → 短暂通知 toast 显示 "Paused 3 losing ads"（已暂停 3 个亏损广告） → 回到按钮。
</structure>

<build>
1. 只用一个 HTML 文件，1440x1440。每一种样式都在 seek(t) 内计算：不用 CSS transitions，不用定时器，不在帧之间保留状态。
2. 弹簧采用闭式阶跃响应。对于多次改变目标值的数值，用多个弹簧相加，使它始终是时间的纯函数。
3. 标签页指示条和开关滑块：两条边缘分别由不同弹簧驱动，让前缘先向前拉伸。
4. 拖动采用直接操纵：按住期间，数值跟随光标；释放后，从当时所在的位置弹回。
5. 不使用音乐。用 numpy 合成 UI 音效，并根据测得的各音效峰值，把它们放在节拍网格上。
6. 用 Playwright 渲染：每帧取 4 个子帧，用 ffmpeg tmix 混合，得到带运动模糊的 60fps 输出。
7. 先在每一拍渲染一帧。修正任何不对齐节拍网格、拥挤或难以阅读的地方。
</build>

<gotchas>
不要给任何会被镜头缩放的元素设置 will-change。被替换的文字需要各自独立的进入/退出时序。使最后一帧与第一帧一致，包括光标的位置和速度，否则循环会卡顿。
</gotchas>

在编写任何代码之前，把按节拍网格排列的状态列表展示给我。
```

## 制作思路（本次分析，非原文要求）

### 目标效果与画面顺序

这条动效要讲清楚广告管理产品的一次工作闭环：连接渠道账户，提出投放需求，查看竞争研究与广告参考，审批投放，调预算，启用自动运行，查看 ROAS，再通过命令暂停表现不佳的广告。品牌推广目的通过产品操作本身呈现，而不是在抽象图形上贴一个 logo。

前半段“输入需求—研究 42 个竞争对手—滚动广告墙”解释信息从哪里来；中段“审批—预算—Autopilot”展示控制方式；后半段“图表—pause—通知”展示查看效果与干预结果。上述数值和英文文案来自原提示词，不能作为实际产品能力或经营效果已经核实的证明。

### 动画方法

围绕同一容器连续变形，让它依次成为输入栏、灵动岛、广告展示区域、审批卡、预算控制和图表。广告墙滚动与停靠、ROAS 曲线绘制属于容器内部内容的动画；它们应与外层 seek(t) 使用同一个时间基准，否则逐帧跳转时会出现不一致。

预算拖动是关键的直接操纵段：按住时数值追随光标，超过最大值时表现拉伸，松手再从当前位置回弹。随后用开关滑块接力变成跨渠道的标签指示条，利用两个边缘分别受弹簧驱动的方式表现液态感。每个文字块独立安排进出时间，尤其要防止长研究文案、审批信息和图表提示气泡挤在形变中的窄容器里。

### 工具与素材

原文明示：一个 1440x1440 HTML 文件、seek(t)、Geist、#FD9543、numpy 合成 UI 音效、Playwright、ffmpeg tmix、每帧 4 个子帧、60fps。明确要求不用音乐；不能因为其他同源模板有配乐，就为本条加上背景音乐。

所需产品素材来自原文明示的 Sprites UI、五个平台 logo、真实广告及广告管理界面内容。可选建议：由产品方提供可用于展示的界面资料、广告样例和数据说明，并以离线画面数据搭建演示；制作宣传动效不需要真的连接、投放或暂停广告。本次只解释方案，没有执行这些操作。原文没有规定必须用 Canvas、SVG 或 GSAP。

### 落地步骤与验收点

1. 先整理真实产品的布局、字体、图标和广告展示方式，再把原顺序放到 120 BPM、7 个小节的状态表中。原文没有明确每小节拍数，排表时应确认而非直接假定总时长。
2. 在写运动代码前核对所有可见文案与数值："Launch ads that convert"、"Researching 42 competitors"、"pause"、"Paused 3 losing ads"，以及 Meta、Google、LinkedIn、TikTok、Reddit 渠道标识；做中文品牌版本时应作为明确改编再替换。
3. 先构建主容器形变，再按顺序接入广告墙、审批、预算拖动、自动运行开关、渠道切换、ROAS 图表与命令通知。逐帧可跳转性是检查点：给定同一个 seek(t) 应得到相同画面，与之前渲染过哪一帧无关。
4. 合成 UI 音效，把测得的峰值对齐到事件节拍。检查音效与点击、完成、切换等动作的对应关系，并确认没有添加音乐。
5. 按原文先渲染每拍一帧的检查图，修正离拍、拥挤、读不清；再用 Playwright 与 ffmpeg tmix 输出带 4 子帧混合的 60fps 动画。头尾验收包括主形状、文案、光标位置与速度，另查图表悬停提示和预算释放的瞬间。以上都是待执行方法，不能作为已经通过的结果。

### 如何替换后复用

复用到其他业务时，保留“输入任务—查看依据—人工确认—调整参数—自动运行—查看指标—发出干预—结果通知”的操作逻辑，并换成产品确实具有的界面与操作。把 Sprites URL、平台 logo、广告墙、ROAS 和广告相关文案作为成套素材替换；不要保留 42 和 3 这种具体数字却换成不支持它们的业务数据。换品牌色或字体时要重新核对背景对比、文字长度和形变容器尺寸，同时继续遵守单形状无切镜、无音乐和轻微过冲等原运动规则。
