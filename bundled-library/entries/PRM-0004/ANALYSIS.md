# PRM-0004 设计逻辑与使用方法

从主体、受众、事实和已有素材推导不同视觉方向，再用同内容样张比较和选择。

## 为什么入选

从零确定网站、品牌页面或产品视觉方向，解释为什么某种风格适合这个项目。 源文具有明确任务、具体步骤和可检查的产物，适合作为高质量候选。此处是结构评审，不是效果认证。

## 原作者公开的方法

以下依据[固定版本原文](https://github.com/Leonxlnx/taste-skill/blob/6010f91a9935f1c167dfc500fb1a475681892e6b/skills/taste-skill/SKILL.md)归纳：原文从主体特有事实出发，把页面写成主张与证据，再从方向库中选择构图、字体、配色和图片方案；使用浏览器截图做 look-and-fix，并区分阅读型页面与工作型应用。

## 我的设计逻辑分析

以下是本次整理者对方法作用的解释，不是作者未公开的内部思考：可辨识的设计来自内容与形式之间的关系。把一家餐馆真实的材料、时间、地点与服务方式转成节奏、字体、色彩和照片，比套用‘高级感’更可追溯。三种方向使用同一份内容，能减少因文案或图片质量不同而误判风格；用户的选择形成具体偏好记录。

## Loop 是否需要、怎样写

**方向确定并有可见样张后最多 3 轮；人负责偏好取舍。**

```text
选择方向后，如有可见样张，最多做 3 轮‘呈现 → 按固定标准评审 → 只修最高影响的问题 → 再呈现’。先固定主体表达、信息层级、品牌一致性、可读性和实际素材使用这五项标准，每轮最多修改 2 个问题。保留同内容、同视口的前后图及修改理由。满足标准即停止；连续一轮无可观察改善、素材不足、出现互相冲突的偏好或达到上限时停止。退化则恢复上一版。涉及用户喜欢哪种风格时记录选项并等待该取舍，不让模型通过自评分替用户决定。没有样张时只做方向论证，不声称完成视觉验证。
```

## 使用示例与边界

- 使用示例：为个人提示词库提供真实分类、检索任务、已有品牌颜色及三张偏好参考，比较知识档案、编辑出版、轻量工具三种方向。
- 不宜直接外推：参考与素材必须可取得；不能编造客户历史、产品截图、用户证言或数据来支撑视觉方案。应用工作台要按任务效率另做判断。
- 证据现状：作者在源文中称参考研究覆盖 247 个站点并提到测试；本次只核实公开文本存在，没有审计样本库、盲评方法或复现结果。不能据此认定改编版有效。
- 实际效果状态：`untested`。已完成的检查仅为来源、文件完整性、分类、版本与文本结构；未进行真实模型生成、用户偏好测试或项目运行。

## 如何验证这条提示词是否对你有效

选择一个代表性任务，冻结输入、模型与运行条件，用原版适用环境和优化版各生成一次；原版依赖不齐时，将基线改为你现用提示词并明确标注。记录输出、失败项、可观察指标和你的取舍理由。先看是否达成上述可检查产物，再记录偏好；一次胜出只是样例证据，不能推广为通用结论。把实际结果写入本条反馈并保留失败样例后，再决定是否生成 v002。
