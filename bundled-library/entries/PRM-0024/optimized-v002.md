向我询问：我希望这个形状变成的 8 到 12 个 UI 状态（例如按钮、加载器、播放器、滑块、开关、标签页、图表、命令面板、短暂通知 toast）；采用纯黑白还是一种强调色；以及一首约 120 BPM 的免版税歌曲（例如 Mixkit，可免费商用）。
</inputs>

<direction>
达到 Dribbble 水准的 UI 动效。只有一个形状，绝不切镜：每个状态都是同一个元素改变尺寸、圆角半径和颜色，同时其内部内容伴随短暂模糊而替换。光标通过真实的点击和拖动驱动每一次变化。采用浅暖灰色画布、黑白组件，以及一种简洁的 UI 字体（Geist）。处处使用弹簧运动，最多只允许极轻微的过冲。镜头通过缩放让每个状态占满画面。最后一帧就是第一帧，从而形成循环。
禁止：弹跳式缓动、粒子爆发、辉光、UI 控件外观上的渐变、粗细不一致的图标描边、无事发生的空档，以及任何看起来像模板的东西。
</direction>

<structure>
120 BPM，7 个小节，每一拍都有事情发生。
按钮 → 加载器 → 对勾 → 灵动岛 → 带播放/暂停形变的音乐播放器 → 拖动进度条调整播放位置 → 它变成音量滑块，拖过最大值时会拉伸 → 开关跟随节拍切换 → 开关滑块变成液态的标签页指示条 → 标签页展开成自行绘制的图表，悬停时显示提示气泡 → 它收拢成 ⌘K 命令入口 → 输入文字进行筛选 → 按下 Enter → 短暂通知 toast → 回到按钮。
</structure>

<build>
1. 只用一个 HTML 文件，画面为 1440x1440 的正方形。每一种样式都在 seek(t) 内根据时间计算：不用 CSS transitions，不用定时器，不在帧之间保留状态。
2. 弹簧采用闭式阶跃响应。对于多次改变目标值的数值，每次变化对应一个弹簧，把这些弹簧相加，因此它始终是时间的纯函数。
3. 标签页指示条的两条边缘分别由不同弹簧驱动，使前缘先于后缘向前拉伸。开关滑块使用相同技巧。
4. 拖动采用直接操纵：光标处于按住状态时，根据它的位置计算数值；释放后，从当时所在的位置弹回。
5. 用 numpy 分析歌曲，得到节拍网格，并从小节的第一拍开始。按测得的峰值位置安排每一个 UI 音效。
6. 用 Playwright 渲染：每帧取 4 个子帧，用 ffmpeg tmix 混合，得到带运动模糊的 60fps 输出。
7. 完整渲染之前，先在每一拍渲染一帧。修正任何不对齐节拍网格、拥挤或难以阅读的地方。
</build>

<gotchas>
绝不要给任何会被镜头缩放的元素设置 will-change，否则文字会渲染模糊。形变容器内替换的文字需要各自独立的进入与退出时序，否则会重叠。让最后一帧与第一帧完全相同，包括光标的位置和速度，否则循环会卡顿。
</gotchas>
