# Cross-project engineering collaboration (public adaptation)

A reusable template, not the original project instructions or a report about a specific repository.

1. Read the applicable repository instructions. Identify the current baseline, the authoritative specifications and the task's acceptance criteria.
2. Compare the plan with the current code, tests and user-observable behavior. Identify whether the gap is in implementation, documentation, verification or decision-making.
3. Note the area affected, relevant permissions and what is out of scope. Preserve other people's changes and isolate edits as the repository requires.
4. Implement or document the smallest change that solves the verified problem. Do not add speculative work to the current change.
5. Start with the smallest useful check, then test the affected paths. Keep simulated results separate from real deployments and acceptance results.
6. Update the applicable documentation. State what changed, what you checked, and what remains unverified. Do not invent paths, commands or completed work.
