# PRM-0002 设计逻辑与使用方法

从产品目的、视觉表达与使用路径评审设计，区分观察、推断和偏好，输出有证据的前三项改进。

## 为什么入选

你觉得页面‘说不上来哪里不对’，或需要评审设计师/AI 的两版方案。 源文具有明确任务、具体步骤和可检查的产物，适合作为高质量候选。此处是结构评审，不是效果认证。

## 原作者公开的方法

以下依据[固定版本原文](https://github.com/pbakaus/impeccable/blob/5cb95eea9c96479f57afe0732a45470d30183326/skill/reference/critique.md)归纳：原文先评设计是否属于这个产品，再结合检测器与浏览器证据；要求评审与检测隔离，避免检测结果过早影响判断，并报告优点、优先问题与证据来源。

## 我的设计逻辑分析

以下是本次整理者对方法作用的解释，不是作者未公开的内部思考：审美判断需要一个参照系：同一版式对艺术展和财务审批可能有不同价值。先判断目的和主体表达，再检查层级与交互，能把偏好转成有条件的建议。将证据和解释分列，是为了让用户能够反驳或验证具体判断，而不是接受一句‘不够高级’。

## Loop 是否需要、怎样写

**首次诊断无需循环；有新版本后最多 2 轮复评。**

```text
只有收到修改后的页面、截图或明确的新证据，才启动复评，最多 2 轮。每轮沿用原目标和前三项问题，逐项记录‘已解决/部分解决/未解决/引入新问题’及证据；只新增会影响主要任务的问题。主要问题已解决即停止。没有新材料、连续一轮没有新增有效证据、出现互相冲突的品牌目标，或达到上限时停止并说明需要用户作出的取舍。不得反复改写同一份意见来伪装进步。
```

## 使用示例与边界

- 使用示例：把同一页面的桌面与手机截图、目标用户和主要任务交给它，要求保留现有品牌，先给前三项问题。
- 不宜直接外推：单张截图只能支持可见视觉判断，不能证明交互、任务完成效率或无障碍表现。
- 证据现状：仓库提供完整评审流程和证据要求；本次未运行其检测器或复现任何评审对照，未获得这版中文提示词的用户效果证据。
- 实际效果状态：`untested`。已完成的检查仅为来源、文件完整性、分类、版本与文本结构；未进行真实模型生成、用户偏好测试或项目运行。

## 如何验证这条提示词是否对你有效

选择一个代表性任务，冻结输入、模型与运行条件，用原版适用环境和优化版各生成一次；原版依赖不齐时，将基线改为你现用提示词并明确标注。记录输出、失败项、可观察指标和你的取舍理由。先看是否达成上述可检查产物，再记录偏好；一次胜出只是样例证据，不能推广为通用结论。把实际结果写入本条反馈并保留失败样例后，再决定是否生成 v002。
