# 审美诊断：把好看与不好看讲清楚

> 中文改编 v001 · 2026-10-23 · 基于 [pbakaus/impeccable](https://github.com/pbakaus/impeccable/blob/5cb95eea9c96479f57afe0732a45470d30183326/skill/reference/critique.md) 的公开指令，已修改。来源、原版依赖和许可见 [SOURCE.md](SOURCE.md) 与 [LICENSE.txt](LICENSE.txt)。实际效果：**未测试（untested）**。

填写或提供 `{{变量}}` 对应材料；没有提供的项目按正文缺失处理规则执行。以下代码块可完整复制：

```text
请对 {{design_material}} 做一次有依据的审美与设计评审。

背景：产品/内容是 {{product_context}}，目标用户是 {{audience}}，首要任务是 {{primary_task}}；必须保留 {{constraints}}。参考偏好为 {{references_or_preferences}}，未提供则不要假定某种风格天然更高级。

先确认看到了什么：截图、可访问页面、源代码或文字描述。缺关键材料时指出缺口；能继续的部分先评。仅有截图时，不推断不可见交互已经可用。

按以下顺序工作：
1. 用一句话解释这份设计试图传达什么、促成什么行为。描述第一眼注意到的主体，以及它是否支持首要任务。
2. 在查看自动检测结果之前，判断它是否体现这个产品自己的内容与特点。指出具体依据；不要把渐变、卡片、留白等元素本身当作好坏结论。
3. 检查信息层级、阅读路径、字体与中文排版、色彩角色、布局节奏、内容密度、品牌一致性。对交互与可访问性，只报告实际看到或测试到的证据。
4. 如有真实检测或交互结果，再与视觉判断交叉核对。将‘观察事实’‘合理推断’‘个人偏好’分开。分阶段思考不等于两个独立评审者。

输出：
- 一句总体判断及适用条件。
- 2 项应保留的优点，说明它们服务什么目的。
- 最重要的 3 个问题：具体位置 → 观察证据 → 对理解或任务的影响 → 最小修改建议 → 如何复查。
- 1 项关键取舍：有哪些合理选项，各自牺牲什么。
- 已检查与未检查的范围。

默认只评审，不修改文件。若用户已授权实现修改，再在授权范围内操作。不要编造用户研究、转化率、浏览器检查或客观审美分数。

Loop 与停止条件：
只有收到修改后的页面、截图或明确的新证据，才启动复评，最多 2 轮。每轮沿用原目标和前三项问题，逐项记录‘已解决/部分解决/未解决/引入新问题’及证据；只新增会影响主要任务的问题。主要问题已解决即停止。没有新材料、连续一轮没有新增有效证据、出现互相冲突的品牌目标，或达到上限时停止并说明需要用户作出的取舍。不得反复改写同一份意见来伪装进步。
```
