# 响应式适配：让任务在不同屏幕与输入方式下成立

> 中文改编 v001 · 2026-10-23 · 基于 [pbakaus/impeccable](https://github.com/pbakaus/impeccable/blob/5cb95eea9c96479f57afe0732a45470d30183326/skill/reference/adapt.md) 的公开指令，已修改。来源、原版依赖和许可见 [SOURCE.md](SOURCE.md) 与 [LICENSE.txt](LICENSE.txt)。实际效果：**未测试（untested）**。

填写或提供 `{{变量}}` 对应材料；没有提供的项目按正文缺失处理规则执行。以下代码块可完整复制：

```text
请将 {{web_page_or_component}} 适配到 {{target_contexts}}，保证 {{primary_task}} 可以完成。

现有技术栈 {{stack}}；当前材料 {{source_or_design}}；必须保留 {{must_keep}}；允许修改范围 {{editable_scope}}；已知问题 {{known_failures}}。

先识别支持的视口、输入方式和使用环境。用户未指定时，可把 320、768、1440 CSS 像素作为初步抽查示例，并说明它们不代表所有设备；正式目标仍以项目支持范围为准。

建立检查矩阵：情境｜主要任务｜可能失败｜验证方法｜证据来源。优先检查：
- 阅读顺序、主要操作与必要信息是否保持可发现。
- 长中文标题、表格、表单和弹层是否溢出或遮挡关键内容。
- 窄屏是否需要重排信息，而不只是缩小字体或隐藏功能。
- 键盘焦点、触摸与鼠标能否完成主要任务；关键功能不能只依赖 hover。
- 与任务相关的方向切换、软键盘、滚动和加载情况。

先找造成问题的布局与组件规则，沿现有组件和断点体系做最小修改。必要时建议表格的横向滚动或替代表达，并说明取舍。不要把专业数据页面一律改成大卡片。

如果涉及拖拽或手势，实际检查开始、移动、释放、取消及与滚动的冲突；仅靠截图不能判断手势通过。所有证据注明是静态审查、模拟视口、合成输入还是真实设备，并写明浏览器或设备。

输出适配方案、实施改动（若授权）、检查矩阵结果、前后证据及未覆盖范围。不把几个视口通过描述成全设备兼容。

Loop 与停止条件：
在用户已授权实现且可运行目标页面时，最多 3 轮‘检查情境矩阵 → 修复最高影响失败 → 复测失败与相邻情境’。每轮保存视口、浏览器、输入方式、操作步骤和前后结果。优先处理主任务受阻、遮挡和误操作，不为循环增加新平台。目标情境通过即停止；连续一轮无法减少已确认失败、缺真机/材料/权限、需要改业务范围或达到上限时停止，列出未覆盖项。新改动导致原情境退化时恢复或修正相关改动。纯建议任务只交付矩阵与方案，不伪造测试结果。
```
