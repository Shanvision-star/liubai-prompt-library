# PRM-0007 设计逻辑与使用方法

从截图、样式或设计文件提取颜色、字体、间距和组件规则，区分观察、测量、推断与建议。

## 为什么入选

已有喜欢的界面或成熟项目，需要形成可以交给后续 AI/设计师使用的规范。 源文具有明确任务、具体步骤和可检查的产物，适合作为高质量候选。此处是结构评审，不是效果认证。

## 原作者公开的方法

以下依据[固定版本原文](https://github.com/google-labs-code/stitch-skills/blob/0337446dadde6f8c94210444e2aa9d546126480f/plugins/stitch-utilities/skills/design-md/SKILL.md)归纳：原文从 Stitch 项目取得屏幕、截图、HTML 和主题信息，生成语义化 DESIGN.md；将色彩、字体、几何、层级、组件和布局描述为后续生成可复用的设计语言。

## 我的设计逻辑分析

以下是本次整理者对方法作用的解释，不是作者未公开的内部思考：截图能展示结果，却很难表达规则。把‘这个蓝色’整理为‘链接色/主操作色’，把间距整理为反复出现的层级，才便于复用。严格区分实测与推断，能避免把截图猜测固化成错误规范；反例和例外也必须留下，否则会把偶然样式当成系统。

## Original / Revised / Reason or Impact

- Original：完整保留 [original.md](original.md)，包括特定工具、占位符与风格约束。
- Revised：提供可单独复制的 [中文优化版](optimized-v001.md)，具体调整如下。
  - 移除 Stitch 工具和字段调用依赖，接受可取得的截图、DOM/CSS、设计文件或已有规范。
  - 为每个值增加来源位置、证据类型和置信范围，截图无法确认的字体/色值不得写成精确事实。

## Loop 是否需要、怎样写

**复杂规范可做最多 2 轮抽样核对；缺材料时停止。**

```text
初稿后可做最多 2 轮‘提取 → 抽样核对 → 修正规则’。优先选择 2 个不同页面或 2 类组件，检查规范能否解释其颜色角色、字体层级、间距及例外；仅有一个组件时说明覆盖不足。每轮只修正有新证据的规则并保存冲突。抽样匹配且未决项已明确即停止；材料不足、同一冲突没有新依据或达到上限时停止，不通过猜测补齐。没有实际渲染复现时不得声称设计系统已复现原界面。
```

## 使用示例与边界

- 使用示例：提供提示词库的列表页和详情页截图及对应 CSS，整理颜色与字体角色，指出两页按钮样式的冲突。
- 不宜直接外推：单张截图无法可靠还原全部字体、状态、断点和交互；提取的是可见证据支持的子集。
- 证据现状：Google Labs 公开仓库提供设计文档提取流程；本次未连接 Stitch 或验证提取结果能复现原设计。
- 实际效果状态：`untested`。已完成的检查仅为来源、文件完整性、分类、版本与文本结构；未进行真实模型生成、用户偏好测试或项目运行。

## 如何验证这条提示词是否对你有效

选择一个代表性任务，冻结输入、模型与运行条件，用原版适用环境和优化版各生成一次；原版依赖不齐时，将基线改为你现用提示词并明确标注。记录输出、失败项、可观察指标和你的取舍理由。先看是否达成上述可检查产物，再记录偏好；一次胜出只是样例证据，不能推广为通用结论。把实际结果写入本条反馈并保留失败样例后，再决定是否生成 v002。
