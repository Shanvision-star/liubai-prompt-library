<rules>
一个 HTML 文件。一个 canvas。
一个 draw(t) 函数。

不用 CSS transitions。
不用定时器。
不在帧之间保留状态。

只有一个形状，绝不切镜。

每个状态都是同一个元素改变尺寸、圆角半径和颜色，同时替换内部内容。

光标通过真实的点击、打字和一次拖动驱动整个序列。

真实 UI。真实数据。不用占位内容。

</rules>
<structure>
120 BPM 的网格。

每个 bea 都有事情发生。

logo → 按钮 → 用户名字段（handle field） → “这是你吗？”（“is this you?”） → 加载器 → pin → 逐渐填满用户的地球 → 匹配结果 → 标签页 → 出席回复 RSVP → 搜索 → logo

</structure>

<motion>
处处使用闭式弹簧，只允许极轻微的过冲。

如果一个数值多次改变目标，每次变化对应一个弹簧，并把它们相加。

内容应在容器开始变形之后进入，并在下一次变形之前退出，使文字永不重叠。

转场使用短暂模糊。

绝不要把黑色直接渐变淡入成强调色，而应让一个强调色元素在状态之间移动。

让标签页指示条的每条边缘分别由不同弹簧驱动，使指示条产生拉伸。

缩放镜头，让每个状态占满画面。

让最后一帧等于第一帧，使整个动画循环。
</motion>

<export>
先在每一拍渲染一帧，排成联系表式的缩略图总览。

修正任何拥挤或出错的地方。

然后在无头 Chrome 中以 60fps 渲染每一帧，对 6 个子帧求平均以产生运动模糊。

通过管道传给 ffmpeg：
H.264 + yuv420p

并行导出所有宽高比。
</export>
