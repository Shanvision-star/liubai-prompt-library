# 制作思路

### 目标效果与状态顺序

核心是让观众始终相信「同一个组件正在改变用途」。按钮、播放器、滑块、开关、标签页、图表和搜索框共享同一个外壳，内部内容在变形期间交接，而不是切到另一张画面。输入阶段要求的是 8～12 个组件状态；原文给出的长序列还包含加载、拖动、输入、确认等中间动作，制作状态表时应把组件状态和操作步骤分列，避免把每个箭头都误算成一个独立组件。

参考顺序先从简单的按钮和加载反馈开始，进入播放器与拖拽，再通过滑块、开关、标签指示器连接到图表，最后经搜索、确认、通知回到按钮。这样的安排让相邻状态具有可继承的外形：滑块的圆形把手可以成为开关的把手，开关的把手又可以拉长成为标签指示器。

### 动画方法

把外壳的位置、宽高、圆角和颜色视为随时间变化的属性，将各状态之间的目标值变化写成闭式弹簧响应的叠加。这样 seek(t) 可以直接得到任意时刻的图像，而不用先播放前面的帧。拖拽阶段应由光标位置直接控制组件数值；释放瞬间再接入回弹，避免组件在按住时自行滞后。

标签指示器和开关把手的两端分别求值，形成「前端先走、后端追上」的拉伸。内部文字、图标另设出入时间，使旧内容退场后新内容才进入。相机跟随当前组件调整构图，但运动幅度应服务于组件可读性。原文同时要求小幅越界与禁止蹦跳，可以理解为允许一次克制的过冲，避免明显连续弹跳；具体弹簧参数并未给定，不能把某组参数冒充原文要求。

### 工具与素材

原文明示：HTML、seek(t)、闭式弹簧计算、numpy、Playwright、ffmpeg 的 tmix；日语 UI 使用 Noto Sans JP，英数字和符号使用 Geist；需要约 120BPM 的歌曲、组件状态和配色输入。Mixkit 是原文列出的歌曲来源示例。

可选建议：先准备一份状态表，列出每个组件的文字、图标、外壳尺寸、光标目标和节拍位置；图标统一描边规则。具体歌曲的使用条件应随实际选曲记录，不把来源站点的名称视为对每首作品的统一授权。原文没有指定 Canvas、SVG 或 GSAP，选择哪种绘制方式属于实施选择。

### 落地步骤与验收点

1. 收齐 3 项输入，先交付按拍排列的状态清单，再编写代码。保留 120BPM、7 小节、约 14 秒的原始节奏描述；音乐分析后再据实际拍点排布动作。
2. 先制作所有静态状态，确认日文内容及字体能正确显示，再把相邻外壳连接成连续变形。此时重点检查布局和内容交接，不先堆叠音效。
3. 加入点击、悬停、拖动与释放轨迹，并让数值、提示气泡和光标动作一致；不让滑块在拖拽过程中脱离光标。
4. 加入相机运动及音频，按测得的声音峰值对齐操作反馈。用每拍 1 帧的预览检查拍点、拥挤和可读性，这是原文明示的全片导出前检查。
5. 按每帧 4 个子帧制作运动模糊，输出 1440x1440、60fps。检查循环接缝的组件状态、文字、光标位置与速度；检查缩放文字未因 will-change 产生模糊、图标线宽一致、没有禁止的光晕或渐变。

补充验收建议：同一时间点先后独立调用 seek(t)，比较画面是否一致，以发现计时器或帧间状态依赖。这是对原文确定性要求的检查办法，未在本次实际运行。

### 替换品牌、文案与数据复用

可保留组件连接关系，替换播放器名称、图表数据、搜索候选项、通知文字及强调色。替换后应重新检查文字长度、图表轴范围与光标目标，不能只换字符串而沿用错误的命中位置。

这份中文译文仍忠实保留「成片界面使用日语」的要求。若要制作中文界面，应将语言与字体改动作为使用时的明确改编，并重新检查字体覆盖、字重及布局；它不是本次翻译自动产生的新要求。
