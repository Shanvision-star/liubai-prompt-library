# 提示框到胶片时间轴交互演示｜中文翻译与制作思路

关联原记录：PRM-0023。独立来源组：awesome-opus5-5-videos · UI动效。

本记录是原英文提示词的中文译文与独立讲解；原文、作者及来源以 PRM-0023 为准。状态：未执行、未实测，以下制作与验收均为后续使用说明。

## 中文翻译

用代码制作一段 12s 动效视频（1920x1080，30fps，使用 1 个 HTML 文件，通过同一个 seek(t) 函数绘制每一帧，用 Playwright + ffmpeg 渲染，并配上原创合成音效）。

故事：在偏白的页面上，一个深色胶囊状提示输入框以真实的按键节奏输入「制作一支发布视频」（原显示文案："make a launch video"）→ 按下 enter，按钮闪成橙色，胶囊输入框向上滑动 → 一条包含 12 个画格的胶片带从左到右逐格盖印出现，按 120 BPM 每拍出现 1 格；每格呈现一个橙色球弹跳的姿态（接触地面时压扁，腾空时拉长，沿真实的弧线运动）→ 播放头扫过胶片带，同时上方的大预览区把这些姿态像翻页动画一样播放 2 次，第 2 次更快 → 胶片带滑出画面，「每一帧都是代码。」（原显示文案："every frame is code."）铺满画面，球沿弧线飞过来，最后落下成为句点。

规则：快速抵达，柔和落定（每帧走过剩余距离的 12–19%）；任何内容都不能完全静止（每次停留时都保持缓慢推进）；错开 2–4 帧；只在快速运动时使用模糊；尺寸要大，在手机上也易读；仅使用偏白色、墨色和 1 种橙色。声音：每次按键都有轻响，按下 enter 时有点击声，每个画格盖印时有一个逐渐升高的音符，球落地时有低沉的撞击声。

先给我看 5 张静帧（输入文字时、胶片带构建到一半时、翻页播放时、标题画面、最后一帧），像严苛的动效导演一样评价它们，修复最严重的 3 个问题，然后再渲染。

## 制作思路（本次分析，非原文要求）

### 目标效果与状态顺序

观众先看到一个简单输入行为，再看到动画如何被拆成画格、由播放头驱动，最后由同一个球完成标题的句点。输入框、胶片带和预览区是 UI 主体；弹跳球既是预览素材，也是收尾转场的连续线索。

顺序应明确分为：输入文字 → enter 确认与输入框上移 → 12 个画格依次出现 → 播放头与预览区同步完成两次播放 → 胶片带退场 → 标题与落点收尾。第二次播放必须比第一次快，但原文没有规定加速倍数，不能自行把某个倍数当成强制参数。

### 动画方法

用 seek(t) 统一计算文字已出现的字符数、输入框位置、当前已出现的画格数、播放头位置、预览姿态和球的位置。胶片画格与预览区应共用同一份弹跳姿态数据，避免「胶片显示的姿态」和「正在播放的姿态」不对应。接触地面时压扁、空中拉长的形变要跟随球的运动阶段，而不是在任何位置随机拉伸。

原文给出每帧推进剩余距离的 12–19%，表达的是逐步靠近目标、越接近越慢的感觉。实施时既要保留这种衰减感，又要让 seek(t) 能独立定位：可选做法是将每段位移的衰减写成按段内帧序号直接求值的形式，而不是依赖上一次绘制留下的位置。这是实现建议，不是原文另附的算法。

原文的「每次停留时缓慢推进」可用很轻的持续位移或镜头推进表达；它不等于让文字不停晃动。运动模糊只用于快速位移，标题与低速停留阶段应保持清楚。错开 2–4 帧用于元素先后到场，不应破坏胶片每拍出现 1 格的主节奏。

### 工具与素材

原文明示：1 个 HTML 文件、seek(t)、Playwright、ffmpeg、原创合成音效；输出为 1920x1080、30fps、12s，盖印节奏为 120 BPM。视觉素材包括深色输入胶囊、按钮、胶片带、播放头、预览区、橙色球和结束标题，配色只用偏白色、墨色和 1 种橙色。

原文没有要求音乐曲目、外部视频、素材库、指定字体或指定声音合成工具。可选建议：先建立同一个球的姿态表与音效事件表，逐项记录按键、enter、盖印和落地时点；选择声音实现方式时，把它标作实现选择，不冒充原作者指定工具。

### 落地步骤与验收点

1. 先排出 12s 时间安排，给输入、逐格盖印、两次回放和标题收尾预留空间。120 BPM 对应每拍 0.5 秒，这是由原文节拍换算的排程参考；画格出现时点应明确，不把 12 个画格误解为整片只有 12 帧。
2. 绘制输入框、胶片带、预览区及球的关键姿态，先确保手机观看时字号和构图可读，再添加动作细节。
3. 让输入字符与按键轻响对应；确认时同步橙色闪烁、点击声和输入框上移。让画格盖印与逐渐升高的音符对应，落地与撞击声对应。
4. 用同一套姿态驱动胶片与预览，检查播放头与姿态同步；第二次播放更快，且退场后球仍能自然接入最终句点位置。
5. 按原文先提供 5 张指定阶段的静帧，指出并修复最严重的 3 个问题，再渲染。静帧能检查层级与布局，但不能单独证明速度、声音和回放同步正确；这些应在之后的运动预览中另外检查。
6. 最终核对 12s、1920x1080、30fps；检查 12 格、两次播放与第二次加速；检查 2–4 帧错序、快速运动才模糊、停留仍有轻微推进，以及球是否准确落为标题句点。

补充验收建议：从不同时间点直接调用 seek(t)，确认预览姿态及 UI 状态可重现；检查音效峰值是否与画面动作对应。本次未渲染或试听，这些检查尚未实施。

### 替换品牌、文案与数据复用

可以把输入文字替换成自家产品支持的命令，把结束标题换成对应卖点，保留输入 → 生成画格 → 预览 → 标题的流程。英文原显示字符串在译文中被保留；实际成片若改用中文文案，需要重新安排打字节奏、标题宽度和最后的标点落点。

还可以把弹跳球换成产品中的简单图形，但需要保持胶片里的姿态、预览内容与收尾元素来自同一对象。品牌强调色可以替换橙色，但这会改变原文「1 种橙色」的约束，应明确作为改编；不要在复用时无说明地增加渐变、额外配色或外部影像。
