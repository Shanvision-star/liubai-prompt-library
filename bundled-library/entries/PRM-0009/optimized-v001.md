# 界面加固：长文本、空状态、错误与重复操作

> 中文改编 v001 · 2026-10-23 · 基于 [pbakaus/impeccable](https://github.com/pbakaus/impeccable/blob/5cb95eea9c96479f57afe0732a45470d30183326/skill/reference/harden.md) 的公开指令，已修改。来源、原版依赖和许可见 [SOURCE.md](SOURCE.md) 与 [LICENSE.txt](LICENSE.txt)。实际效果：**未测试（untested）**。

```text
请检查并在授权范围内加固 {{ui_scope}} 的边界状态。

用户主要操作 {{critical_actions}}；现有实现 {{implementation}}；已知接口与权限约定 {{api_and_permission_contract}}；支持的语言和设备 {{supported_contexts}}；可修改范围 {{editable_scope}}。

先读取当前行为，列出与任务有关的状态矩阵：状态/触发条件｜用户看到什么｜仍可做什么｜如何恢复｜需要什么证据。至少考虑正常、加载、空、错误和无权限；不适用项说明理由。

根据风险选取边界输入：超长中文与数字、空值、Emoji、较多条目、必要的多语言/RTL、网络超时、断线、重复点击、取消与重试。不要为覆盖清单添加不在项目范围内的功能。

设计与修复原则：
1. 错误说明失败了什么、用户可采取什么动作；不暴露敏感内部信息，也不只给一个‘失败’。
2. 可恢复错误尽量保留用户输入和操作上下文。加载、空结果和权限不足需明确区分。
3. 长文本不要压坏布局；截断关键信息时提供查看完整内容的办法。
4. 重复操作按接口约定处理。前端禁用按钮不等于服务端幂等；没有契约依据，不盲目重试可能重复产生副作用的请求。
5. 保持键盘可达、焦点合理、状态不只依赖颜色。修改必须复查正常路径，不能用隐藏错误换取表面正常。

能安全模拟的状态可在本地测试，并明确标注模拟来源。真实接口与业务成功需要单独证据；未经授权不要在生产环境制造错误。只交付设计时给规格和验证方案，不声称已实现。

输出按影响排序的问题、状态与恢复设计、实际改动和验证结果。把未实现、未验证、外部依赖分别写清。

Loop 与停止条件：
对已授权修改且能安全构造的状态，最多 3 轮‘触发失败 → 记录预期与实际 → 修复 → 重跑失败与正常路径’。先处理数据丢失、主任务受阻、权限误导和重复提交，再处理视觉问题。每轮记录输入、状态来源、步骤、修改和结果。已选状态通过且正常路径不退化即停止；缺少接口约定或测试能力、连续一轮无新进展、修改超出范围或达到上限时停止并报告。不能真实验证的场景保留为待验证，不能通过删除场景或吞掉错误让清单变绿。
```
