# 制作思路

### 目标效果

这条提示词关注卡片内部不同层级的运动节奏，以及修改后能否用截图验证。卡片承担主体，标题和元数据提供信息层级；280ms、220ms、160ms 是各层的动画时长，60ms 是元素之间的错开间隔，不是把整个动画限定为 60ms。原文没有指定卡片必须从哪个方向出现，也没有规定透明度、缩放幅度、缓动曲线或过冲容差。

### 画面与状态顺序

可先把画面整理为卡片容器、标题、元数据三个层级，建立“初始状态 → 各层运动中 → 稳定终态”的状态表。把卡片、标题、元数据依次错开，是可供实施时确认的一种编排建议；原文并未规定严格的先后次序，也没有要求等卡片完全停止后标题才开始运动。

实施前应明确哪些元素参与 60ms 的错开：是多张卡片彼此错开，还是卡片内部各元素错开，或两者分别编排。原文只写了“各元素之间”，无法据此确定分组。将分组与开始时间写入时序表，再套入三种时长，能避免把时长和延迟相加后误认为原文规定了某个总时长。

### 动画方法

原文明示使用 GSAP 时间轴组织动画。制作时可用同一时间轴统一管理各层的开始时间与持续时间，便于暂停和定位检查。卡片的位移或缩放、标题及元数据的透明度变化都只是可选表现方式，需按已有设计确定，不能当作原文要求。

逐帧检查的重点是过程是否超出预期：例如卡片在运动峰值时越过容器边界、标题与元数据短暂重叠、动画结束后仍有位移，或字体未就绪导致截图跳动。这些是本次提出的检查示例。原文要求检测过冲或错误，但没有定义哪些过冲可以接受，也没有给出比较基准或像素阈值。

### 工具与素材

- 原文明示的工具：GSAP、Playwright；原文明示的方法：截图对比、逐帧推进、局部修补后复查。
- 实施所需但原文未提供的材料：卡片视觉稿或已有页面、真实标题与元数据、预期初态和终态，以及允许的运动范围。
- 可选建议：使用固定字体与固定数据的测试页面，减少内容变化对截图比较的干扰。原文没有要求 Canvas、视频编码、音乐、特定画布尺寸或帧率，也不需要从仓库复刻技术标签推导这些要求。

### 落地步骤与验收点

1. 确定卡片、标题和元数据对应的实际元素，确认 60ms 错开的分组与顺序；列出开始时间、持续时间和预期终态。
2. 按已确认的时序搭建 GSAP 时间轴。核对卡片 280ms、标题 220ms、元数据 160ms、元素错开 60ms 是否分别对应正确对象。
3. 准备 Playwright 检查流程，固定页面内容与显示条件。原文未给出目标帧率，应在实际项目中先明确采样帧率，再按该帧率逐帧推进；不要把某个假定帧率写成原要求。
4. 对比运动开始、各层衔接、最大位移与结束附近的连续帧，结合完整逐帧序列检查过冲、重叠、裁切、闪烁及终态偏差。比较标准需在执行前依据设计稿确认。
5. 只修补已发现的问题，例如某层开始时间、位移范围或裁切关系；修补后复查受影响的帧，并检查是否破坏原有时长与错开约束。原文要求持续修补直至通过，没有给定循环上限。若实际执行需要时间或轮次预算，应另行约定并说明未通过项，不能把预算或停止条件伪称为原文内容。

验收时应同时看“参数正确”和“画面正确”：时间轴值符合四项毫秒约束，截图也符合确认过的视觉基准。仅看到代码中存在这些数字，不能说明动画效果已经验证。本条尚未进行任何上述检查。

### 替换内容复用

可以将卡片换成商品、任务、数据指标或文章摘要，替换标题、日期、金额、状态等真实字段，并保留层级对应关系。更换品牌字体、字重或数据长度后，应重新检查换行、容器边界和运动中的文字重叠；如果卡片数量变化，也要重新确认 60ms 错开的分组与整体结束时间。280ms、220ms、160ms、60ms 是此原提示词的明确参数；若为其他产品调整，应作为新的改编要求记录，避免与忠实翻译混在一起。
