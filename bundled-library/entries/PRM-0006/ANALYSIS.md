# PRM-0006 设计逻辑与使用方法

先确定内容、行为、视觉角色和布局，再沿现有技术栈构建有辨识度的界面。

## 为什么入选

已明确目标和范围，需要把内容、视觉方向转成页面或组件。 源文具有明确任务、具体步骤和可检查的产物，适合作为高质量候选。此处是结构评审，不是效果认证。

## 原作者公开的方法

以下依据[固定版本原文](https://github.com/anthropics/skills/blob/dbd4588f9e1033efb41dad4bef2f7947c8993d44/skills/frontend-design/SKILL.md)归纳：原文强调从真实客户、内容和受众出发，先给精简的设计规格与布局，再构建；字体、图像、布局和文案共同表达主体，并要求检查移动端、焦点及减少动态效果偏好。

## 我的设计逻辑分析

以下是本次整理者对方法作用的解释，不是作者未公开的内部思考：先约束内容和主要行为，再选择表达方式，可以避免漂亮界面与实际任务脱节。少量语义化的样式角色让实现保持一致；保留一个有意义的视觉重点、让其余部分支持它，比每个组件都争夺注意力更容易形成整体。

## Original / Revised / Reason or Impact

- Original：完整保留 [original.md](original.md)，包括特定工具、占位符与风格约束。
- Revised：提供可单独复制的 [中文优化版](optimized-v001.md)，具体调整如下。
  - 明确设计稿与代码交付两种范围，沿用已有组件、客户端和类型，避免为风格重建系统。
  - 将风格建议绑定到产品语境，不把特定字体、布局或装饰当作通用禁令。
  - 加入关键状态、真实内容边界、可观察验收与三轮修正上限。
- Reason / Impact：让方法能跨项目复用并暴露证据缺口；这不是逐字翻译，也不能视为与原技能流程等效。

## Loop 是否需要、怎样写

**实现后建议检查修正，最多 3 轮；纯文字方案只做一致性检查。**

```text
当已授权实现且可以运行检查时，最多 3 轮‘构建/更新 → 渲染与关键任务检查 → 修正 → 复查’。首轮固定标准：主任务可完成、内容真实且完整、层级清楚、目标视口无阻断性溢出、关键状态可理解、已有功能不退化。每轮最多解决 3 个最高影响的问题，保留前后截图和相关测试结果。标准通过即停止；同一阻塞连续出现且没有新证据、需要超出范围修改、达到上限或无法运行时停止并报告。未运行的浏览器、接口或真机检查不得标为通过。纯方案任务不假装执行实现循环。
```

## 使用示例与边界

- 使用示例：为本机提示词库设计‘搜索—筛选—查看原文/优化版—复制’主路径，复用已有技术栈和数据结构。
- 不宜直接外推：只给设计规格不能证明页面可交互；有代码也不能自动证明浏览器渲染、接口连通或真实业务成功。
- 证据现状：官方技能仓库提供完整前端设计指令；来源身份只能证明出处，不能证明该提示词在你的项目必然更好。本次未运行页面生成或模型对照。
- 实际效果状态：`untested`。已完成的检查仅为来源、文件完整性、分类、版本与文本结构；未进行真实模型生成、用户偏好测试或项目运行。

## 如何验证这条提示词是否对你有效

选择一个代表性任务，冻结输入、模型与运行条件，用原版适用环境和优化版各生成一次；原版依赖不齐时，将基线改为你现用提示词并明确标注。记录输出、失败项、可观察指标和你的取舍理由。先看是否达成上述可检查产物，再记录偏好；一次胜出只是样例证据，不能推广为通用结论。把实际结果写入本条反馈并保留失败样例后，再决定是否生成 v002。
