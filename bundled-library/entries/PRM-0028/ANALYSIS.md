# 制作思路

### 目标效果与画面顺序

这条把“一个编辑器完成一次制作”的过程压缩成 14 秒：吉祥物启动，进入播放、加载、时间轴、关键帧和曲线编辑，再展示帧计数、渲染、导出，最后回到吉祥物。观众持续追踪的是同一个主体形状；各界面只是它的不同状态。原文的 0.0～12.0 时间点就是分镜锚点，12.0 之后还要完成回到开头的衔接，不能把这些节点误当作彼此独立的切镜。

### 动画方法

原文让形状和相机使用两套不同的弹簧参数：形状以 0.72 阻尼、0.35s 稳定，相机以 1.0 阻尼、0.6s 稳定。这样主体先到位，相机稍后跟上，形成空间运动的层次。实现时应把相机变换与主体尺寸、圆角等属性分开计算，避免相机缓慢稳定把主体自己的响应也拖慢。这是对原文参数关系的实现解释。

`window.renderAt(t)` 的纯时间计算是可复查的基础：无论先访问 7.0s 还是 2.5s，同一时间应得到相同图像。点击、文字、进度、光标都要能由传入时间确定，不能依赖前一帧累计结果。`t - 14*floor(t/14)` 负责把时间折回同一周期，但它本身不能保证首尾所有属性连续；光标位置、主体状态和相机仍需共同对齐。

### 工具与素材

原文明示：一个 HTML 文件、Canvas 2D、指定字体与颜色、闭式弹簧、`window.renderAt(t)`、`?t=` 定格、4 子帧运动模糊、H.264 及 60fps。原文没有指定 Playwright、GSAP、音乐或某个编码程序，不能把其他条目的工具要求移入本条。

可选实施建议：先整理一张颜色、圆角、字体和状态尺寸表；准备吉祥物的像素形象，以及时间轴、关键帧和贝塞尔编辑器的界面元素。若需要自动导出，可另选浏览器逐帧采集工具与兼容 H.264 的编码工具；这是后续实现选择，不是原作者指定工具。

### 落地步骤与验收点

1. 按原文时间点画出分镜，标明主体占画面 50% 的布局、相机视野和光标接触位置，再确认颜色与字体输入。不要先把所有界面各做一遍后再硬接。
2. 先做可定格的无音效骨架，逐个时间点检查形状位置、尺寸、圆角和内容；随后加入两套弹簧、内容的 12px 模糊及 0.15s 切换。
3. 单独处理时间轴拖动、关键帧越界弹回、字词垂直滚动、两次涟漪和绘制入场的先后关系。光标要追踪运动中的目标，而不是只对准目标的起始位置。
4. 在首次渲染后按原文检查每拍附近的 5 帧。原文没有定义取样偏移，也没有说“前后各 5 帧”；具体采样位置需在实施时说明。重点看字符重叠、模糊尚未结束就开始描线、光标脱离拖拽对象，以及 65 px/frame 的速度限制。
5. 检查 `?t=` 是否精确定格、任意顺序渲染同一时间是否一致；按 14 秒和 60fps 核对输出时长及帧序列，检查实际导出文件的首尾图像与循环接缝。4 子帧是运动模糊的采样要求，不是把成片帧率变成 240fps。

### 如何替换品牌与数据复用

可以把像素吉祥物换成自己的品牌角色，把编辑器状态换成相同逻辑的产品流程，但仍要让同一个主体连续变形。界面中的 `export mp4` 与 `840 frames rendered` 是原文指定显示文案；若改成自己的导出命令或结果，应在复用版本中明确记录改动，并让显示的计数与新制作规格一致。改变总时长后，原式中的周期 14、状态时间表和回环检查也需要同步调整；不能只改某一处数字。
