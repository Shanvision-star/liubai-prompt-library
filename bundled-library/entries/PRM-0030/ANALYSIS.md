# 制作思路

### 目标效果与画面顺序

这条演示“输入需求 → 制作任务展开 → 时间轴与预览 → 完成通知”的产品流程。主形状从输入栏依次变成黑圆、进度环、预览窗口和轻提示，再回到输入栏；四个任务标签与预览中的行星是围绕主形状运动的辅助元素。因而“一个形状讲故事”不等于整屏只能出现一个图形，而是主载体不能靠切镜被另一场景替换。

原文给出 120 BPM 和 24 拍；按恒定 120 BPM 计算，每拍 0.5 秒，24 拍约 12 秒。这是参数推算，原文并未另外写一条固定“12 秒”要求。各事件具体占几拍没有逐项指定，可在分镜阶段分配，但每拍都要有可观察的动作，不能把所有事件挤在前半段后长时间停住。

### 动画方法

核心是把主圆角矩形的宽、高、圆角、位置与颜色当成可随时间求值的属性。目标变化时叠加闭式弹簧阶跃响应，`seek(t)` 直接求当前画面，而不是依次执行上一帧留下来的动画。这样相机缩放、按钮收缩、预览展开都能在同一时间轴对齐，并能跳到任意拍检查。

文字是独立的一层：输入文字用 `floor(progress × length)` 逐字显示；文字标志通过遮罩边界逐字升起；容器变形时，旧文字先退、新文字再进，避免两套文案叠在一个狭小容器内。原文禁止场景交叉淡化，同时允许文字自身淡入淡出；这两项针对的层级不同，不能误把文字淡入淡出也全部删掉。

### 工具与素材

原文明示：单个 HTML、1440x1440 画布、`seek(t)`、Inter、Playwright、60 fps、H.264 CRF 16、`loudnorm` 与 -14 LUFS；还需单词产品名、强调色、约 120 BPM 的免版税音乐，以及点击、弹出和提示音。原文没有指定 Canvas 2D，也没有指定 GSAP、numpy、4 子帧或 6 子帧，不能从相似提示词搬入这些硬性要求。

可选实施建议：可以另选合适的绘制方案，以及支持 H.264 和 `loudnorm` 的编码工具，例如 ffmpeg；工具名称属于实现建议。音乐示例的使用条件来自原提示词，真正制作时仍需根据选中的具体音轨确认可用素材，而不是把“Mixkit”这个名字视作任意素材的统一许可。

### 落地步骤与验收点

1. 先按 24 拍列出主形状、四个标签、播放头、行星、文字标志及光标各自的状态。确定主形状从一个状态到下一个状态时保留的位置关系，先做每拍静帧布局。
2. 实现可直接定格的 `seek(t)`，加入主形状各属性的弹簧链，再加入相机缩放。任意两次访问同一时间，画面应一致；禁止依赖 CSS transitions、定时器和跨帧累计状态。
3. 把四阶段进度、标签飞入时间轴、播放头扫过、轨道绘制和字母从遮罩升起衔接起来。行星最终成为勾选标记，是预览内容与完成提示之间的视觉连接，应保留这一动作因果。
4. 将真实点击放在对应变化前，按音轨实测节拍和音效峰值对齐声音。这里的“真实点击”是演示中可识别的操作行为，不代表本次已经进行真实产品交互测试。
5. 先检查每拍一张静帧：主内容是否填满方形画幅、字是否可读、四个标签是否拥挤、是否偏拍；再检查快速过渡期间的裁切和文字退出时机。最后检查首尾主体、空输入栏与光标位置一致，并核对导出的 60 fps、H.264 CRF 16 和 -14 LUFS 目标。循环中不得出现空拍、场景交叉淡化或被禁止的视觉效果。

### 如何替换品牌与数据复用

最直接的复用入口是单词产品名和强调色。可把四个标签替换成自己产品的四个真实处理阶段，把时间轴与预览内容替换成产品实际输出，但要保留“输入 → 处理 → 预览 → 完成 → 回到输入”的连续变形关系。`Rendered in code · 60 fps` 是原文指定的界面文案，复用时如改成别的技术或帧率，应更新文案并标明是改编，不能让界面声明与实际输出不符。若改变产品名长度，还需重新检查遮罩、逐字升起和方形画幅中的留白。
