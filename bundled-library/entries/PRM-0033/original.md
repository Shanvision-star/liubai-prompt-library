## 中文翻译

为 Sahi Trading Terminal 制作一段自包含、赏心悦目、令人惊叹的动画。它应从黑色画面上的一个点开始，然后让多个窗口出现在画面中，例如图表（Charts）、持仓（Positons）、期权链（Option Chain）和自选列表（Watchlist）。在多个尺度上放大和缩小。最后，相机拉远，让桌面看起来像空间中的一个点。然后再次拉近，展示横屏模式的移动端屏幕，一半显示图表，另一半显示期权链。视频以「在 SAHI 上进行单屏交易」（原文：Sjngle Screen Trading on SAHI）结束。

使用 javascript 来制作。要细致且准确。视觉效果应令人惊艳。

## 制作思路（本次分析，非原文要求）

### 目标效果与状态顺序

这条提示词展示的是一个交易工作台如何从桌面多窗口，转为移动端单屏分区。叙事顺序是「黑底单点 → 图表、持仓、期权链、自选列表等窗口出现 → 多尺度缩放观察 → 整个桌面缩成远处一点 → 再拉近显露横屏手机界面 → 单屏交易结束文案」。终点的图表与期权链应能在前面的桌面场景中找到对应关系，才能让设备转场具有连贯性。

### 动画方法

原文只规定多尺度缩放，没有指定必须使用三维引擎。可选实施方式是把桌面各窗口放进一个共同场景容器：窗口分别控制入场位置与透明度，整体容器承担镜头缩放。缩小到点之后，再让横屏移动端容器从相同视觉位置放大，以承接前一镜头。

若采用这种二维做法，窗口内容、容器缩放与相机观察范围需要分开控制；否则缩放会让表格文字长期过小。可以在窗口进入后暂时聚焦重点区域，在转场时收起细节。具体缓动、镜头停留时间、窗口先后顺序与节奏是后续制作选择，原文没有给出数值。

### 工具与素材

原文明示的技术只有 javascript；指定产品是 Sahi Trading Terminal，内容包含图表、持仓、期权链、自选列表，以及横屏移动端两个各占一半的区域（具体排布未规定）。原文要求自包含、细致且准确，但没有提供产品截图、数据、色值、尺寸、帧率或明确时长。

可选建议：制作前准备目标版本的桌面与移动端界面参考、品牌标识和获准使用的示例数据，确认「图表占一半、期权链占另一半」的具体排布。HTML/CSS 或 Canvas 都可作为实现选择；不要将其写成作者指定的工具。若没有真实界面参考，应明确是概念演示，不能声称准确复刻了产品。

### 落地步骤与验收点

1. 先确认产品界面参考、输出画幅、时长和结束标题的实际写法。原文的拼写保留在资料中；成片是否修正拼写是制作时需要明确的文案决定。
2. 制作四类窗口的静态样式，检查窗口标题、表格列、图表轴和示例数值是否一致。演示数据应清楚标明用途，不把虚构界面当成真实交易结果。
3. 排布窗口出现与多尺度缩放，让观众能分辨每类窗口，再制作「桌面缩为点 → 移动端展开」的连接段。
4. 建立横屏移动端画面，明确两半分别承载图表和期权链，最后出现原文要求的结束信息。
5. 验收时逐段核对：开头是否黑底单点；四类窗口是否出现；是否具有多个缩放尺度；桌面是否缩为点；移动端是否横屏且两区内容正确；结束信息是否对应 SAHI 的单屏交易主题。

补充验收建议：检查缩放过程中边缘是否裁切、文字是否在重点展示阶段可读、从点展开时是否突然跳位，以及自包含交付是否缺少依赖资源。本次没有制作或播放成片，以上仅为验收计划。

### 替换品牌、文案与数据复用

可把 SAHI 替换为其他多面板软件，例如分析后台或设计工具，但应同时替换窗口名称、图标、示例数据、移动端功能和结束文案。复用的是「复杂桌面 → 汇聚一点 → 简化移动端」的镜头结构，不是把原品牌标识留在新产品界面中。更换产品后，重新确认最终分区是否真实存在；若改成其他分区形式，应明确这是对原提示词的改编。
