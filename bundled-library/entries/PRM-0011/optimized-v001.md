# UI 文案减法：布局自解释，保留必要标签与可访问名称

> v001 · 2026-10-25 · 基于用户提供的中英文素材整理。原文独立保留；效果状态：untested。

```text
请精简 {{ui_scope}} 的界面文案，让信息层级、位置、分组和交互承担已有的解释工作。

Avoid unnecessary supporting text, descriptive copy, and redundant UI microcopy. Let the layout do the explaining.

- 删除不必要或重复的次级标签、辅助说明，以及仅复述布局、标题或显而易见操作的文案。
- 保留识别字段和执行操作所必需的表单标签、控件名称，以及完成任务必需的输入要求、单位、状态与错误恢复信息。
- 只有含义在当前上下文中持续清楚时，才省略重复的可见标签；不要为了整洁让用户猜测字段或操作的含义。
- 删除视觉上的重复文案时，保留控件在代码中的可访问名称及其关联。不要假定相邻按钮会自动给输入框命名，也不要只依赖输入后消失的占位符。
- 例如：搜索框旁已有“搜索”按钮时，可以省略重复的可见“搜索”标签，但输入框仍必须有自己的可访问名称，按钮名称也要保留。
- 修改以界面文案及必要的标签关联为限，保持任务行为清楚。交付时简短列出删除了什么、保留了什么及理由；只有截图或设计稿时，将代码和读屏检查标为未验证。

可选执行约束：
一次性文案整理无需循环。实际修改界面且有检查条件时，最多 2 轮：删减重复文案 → 检查视觉理解与控件可访问名称 → 仅修复已发现的问题。每轮保留前后对照，确认字段仍可识别、主要任务仍可完成、输入要求及错误恢复信息仍完整；发现退化就恢复相关内容。检查通过立即停止；没有新证据、连续一轮无改善、缺关键材料或达到上限时停止并说明未验证项。没有实际读屏测试，不宣称读屏体验已验证。
```
