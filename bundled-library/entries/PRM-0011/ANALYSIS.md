# PRM-0011 设计逻辑与 loop

## 核心逻辑

用户明确要求删掉重复解释布局的文案，同时保留必要的表单标签、控件名称和可访问名称。

本次整理的理解：文案是否保留，应看它是否提供了用户完成任务所需的新信息。布局已经充分表达的内容可以精简；用于识别字段、理解状态或恢复错误的信息仍有实际作用。可见文字与程序中的可访问名称承担不同职责，需要分别核对。

搜索示例中的“可以省略”有条件：可见上下文持续清楚，输入框仍有独立、可靠的可访问名称。邻近按钮的名称不能被直接视为输入框名称。

## 是否需要 loop

**条件适用。** 单次文案整理无需循环；下面是实际修改界面时可选的执行建议，轮次上限是本次整理新增。

```text
一次性文案整理无需循环。实际修改界面且有检查条件时，最多 2 轮：删减重复文案 → 检查视觉理解与控件可访问名称 → 仅修复已发现的问题。每轮保留前后对照，确认字段仍可识别、主要任务仍可完成、输入要求及错误恢复信息仍完整；发现退化就恢复相关内容。检查通过立即停止；没有新证据、连续一轮无改善、缺关键材料或达到上限时停止并说明未验证项。没有实际读屏测试，不宣称读屏体验已验证。
```

## 使用与验证范围

- 适用：清理已有页面或组件中的重复标签、说明与微文案。
- 交叉素材：[PRM-0003 设计减法](../PRM-0003/optimized-v001.md)。
